   Public subnet A:    _______________________________
   Public subnet B:    _______________________________
   Private subnet ID:  _______________________________

   Already created a VPC with only one public subnet? Do this before section L:
   VPC → Subnets → Create subnet
   - VPC: notes-net
   - AZ: a DIFFERENT one (e.g. us-east-1b if the first public is in us-east-1a)

--------------------------------------------------
D. NACL (subnet firewall) — create, keep it open
--------------------------------------------------

A NACL sits on the subnet. The default NACL already allows everything.
We create one so you have seen the screen. Do not deny SSH unless
the tutor is watching — it is easy to lock yourself out.

1. VPC → Network ACLs → Create network ACL
   Name: notes-nacl
   VPC: notes-net
   Create

2. Select notes-nacl → Inbound rules → Edit inbound rules → Add rule
   Rule 100, All traffic, Allow, Source 0.0.0.0/0 → Save
3. Outbound rules → same: Rule 100, All traffic, Allow, 0.0.0.0/0 → Save
4. Subnet associations → Edit → tick the public and private subnets → Save

  [ ] NACL created and associated (allow all)

1. EC2 → Security Groups → Create security group

   VPC: notes-net

     HTTP    TCP    80    Source 0.0.0.0/0     (the load balancer and browsers)

   Create.

G. Open SSH from My IP — then SSH works
--------------------------------------------------

"My IP" is YOUR laptop/home address. That is enough for SSH with the .pem file.

The orange Connect → EC2 Instance Connect button in the BROWSER does NOT
come from your IP. It comes from AWS. If you only add My IP, that button
still fails. That is expected. Use A or B below. Do NOT open 0.0.0.0/0 on 22.

1. EC2 → Security Groups → sg-hello → Edit inbound rules → Add rule
   Type: SSH
   Port: 22
   Source: My IP
   Save rules

2. Pick one way in:

   A. From your laptop (matches the My IP rule)

      Git Bash, in the folder where you saved notes-class.pem:

        ssh -i notes-class.pem ec2-user@PUBLIC_IPV4

      (Windows PowerShell:  ssh -i notes-class.pem ec2-user@PUBLIC_IPV4)

   B. Browser Instance Connect (extra rule required)

      Edit inbound rules again → Add rule
        Type: SSH
        Source: Prefix list
        Choose:  com.amazonaws.REGION.ec2-instance-connect
        Example Mumbai:  com.amazonaws.ap-south-1.ec2-instance-connect
        Example Virginia: com.amazonaws.us-east-1.ec2-instance-connect
      Save.
      Then Instances → hello-a → Connect → EC2 Instance Connect → Connect.

3. In the shell type:
   hostname
   curl -s http://127.0.0.1
   You should see Hello from APP-A
   exit

USE CASE — never leave SSH open to the world
4. You should see 22 from My IP (and maybe the Instance Connect prefix list).
   You should NOT see 0.0.0.0/0 on port 22.

  [ ] SSH works after the My IP rule
  [ ] I did not set SSH to 0.0.0.0/0

K. Create NAT Gateway — then the private VM can go out
--------------------------------------------------

NAT is billed. Create it only after the failure in J. Delete it in section Z.

1. VPC → NAT gateways → Create NAT gateway
   Name: notes-nat
   Subnet: the PUBLIC subnet   (NAT must sit in public)
   Elastic IP: Allocate Elastic IP  (the wizard can do this)
   Create NAT gateway
   Wait until State = Available  (can take a few minutes)

2. VPC → Route tables → the PRIVATE subnet’s route table → Routes → Edit routes
   Add route:
     Destination  0.0.0.0/0
     Target       NAT Gateway   (pick notes-nat)
   Save.

3. Go back to the private-nat-test shell (Connect again if it dropped).
   Wait 30 seconds, then:

   curl -I --max-time 15 https://example.com

   You should see HTTP/2 200 or HTTP/1.1 200.
   Outbound internet now works. Inbound from the internet still does not
   (still no public IP). That is what NAT is for.

  [ ] NAT Available
  [ ] Private route 0.0.0.0/0 → NAT

N. Lambda + S3 trigger
--------------------------------------------------

1. Search: Lambda → Create function
   Name: notes-s3-logger
   Runtime: Python 3.12  (or the Python the console offers)
   Architecture: x86_64
   Create function

2. In the code box, replace the sample with:

import json

def lambda_handler(event, context):
    print("S3 event:")
    print(json.dumps(event))
    for rec in event.get("Records", []):
        b = rec["s3"]["bucket"]["name"]
        k = rec["s3"]["object"]["key"]
        print("Uploaded:", b, k)
    return {"ok": True}

3. Deploy  (orange button). Do not skip Deploy.

4. Configuration → Permissions → click the role name
   This opens IAM. Add a permission if the wizard did not:
   the role needs CloudWatch Logs (usually already there).

5. Back to the Lambda function → Add trigger
   Source: S3
   Bucket: the bucket from section M
   Event type: All object create events
   Acknowledge the recursive warning → Add
   If the console asks to add a resource-based policy, allow it.

6. S3 → your bucket → Upload a new file, e.g. trigger-me.txt → Upload

7. Lambda → Monitor → View CloudWatch logs
   Open the newest log stream.
   You should see a line:  Uploaded:  your-bucket  trigger-me.txt

That is the use case: a file landing in S3 woke a function. No server to stop.
