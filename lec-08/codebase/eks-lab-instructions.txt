M. Break, read, undo  (three unhappy states)
--------------------------------------------------

Keep kubectl describe and kubectl logs as your two tools.
You are not guessing. You are reading Events.


M1. ImagePullBackOff  (wrong tag)

  kubectl set image deploy/notes notes=$URI:no-such-tag
  kubectl get pods
  kubectl describe pod -l app=notes | tail -30

You should see ImagePullBackOff / ErrImagePull.
The node asked ECR for a tag that does not exist.

Undo:

  kubectl rollout undo deploy/notes
  kubectl rollout status deploy/notes
  kubectl get pods

Pods Running again. Refresh the page.


M2. CrashLoopBackOff  (process exits)

  kubectl set env deploy/notes CRASH=1
  kubectl get pods -w

Wait until you see CrashLoopBackOff. Ctrl+C stops the watch.

  kubectl logs -l app=notes --tail=20
  kubectl describe pod -l app=notes | tail -20

Logs should say CRASH=1 is set. Exiting on purpose.

Undo:

  kubectl set env deploy/notes CRASH-
  kubectl rollout status deploy/notes
  kubectl get pods


M3. Pending  (the node has no room for this request)

  kubectl patch deploy notes --type json -p "[{\"op\":\"replace\",\"path\":\"/spec/template/spec/containers/0/resources/requests/memory\",\"value\":\"8Gi\"}]"
  kubectl get pods
  kubectl describe pod -l app=notes | tail -25

New Pods sit Pending. Events say Insufficient memory (or similar).
The cluster did not start them. They are waiting.

Undo:

  kubectl rollout undo deploy/notes
  kubectl rollout status deploy/notes
  kubectl get pods

If undo does not clear Pending: kubectl delete deploy notes
then apply deployment.yaml again (IMAGE still :l8).

P. Probes  (simple) — do this after M is healthy
--------------------------------------------------

Your Deployment already knocks on GET /health.
P1 asks liveness to knock on a door that does not exist → kubelet restarts the container.
P2 asks readiness to knock on that door → Pod stays up, Service stops sending traffic.


P1. Liveness  (are you alive?)

  kubectl patch deploy notes --type json -p '[{"op":"replace","path":"/spec/template/spec/containers/0/livenessProbe/httpGet/path","value":"/nope"}]'
  kubectl get pods
  kubectl describe pod -l app=notes | tail -25

Restarts go up. Events say Liveness probe failed.
The process is not answering /nope. kubelet restarts it.

  kubectl rollout undo deploy notes
  kubectl rollout status deploy notes


P2. Readiness  (should the Service send people here?)

  kubectl patch deploy notes --type json -p '[{"op":"replace","path":"/spec/template/spec/containers/0/readinessProbe/httpGet/path","value":"/nope"}]'
  kubectl get pods
  kubectl get endpoints notes
  kubectl logs -l app=notes --tail=5

Pods show Running 0/1 Ready. Endpoints look empty.
The process is still up (logs still print). The door is shut.
Refresh http://HOST/ — the page hangs or fails.

  kubectl rollout undo deploy notes
  kubectl rollout status deploy notes
  Refresh the page. It works again.

  [ ] liveness: Restarts went up, then undo
  [ ] readiness: 0/1 Ready, page hung, logs still printed, then undo


--------------------------------------------------
Q. RBAC  (simple) — no second AWS user
--------------------------------------------------

Lecture 7’s access entry made YOU cluster admin. That is why CloudShell can apply and delete.
This demo creates a tiny identity that may only get/list Pods.

  kubectl create sa notes-reader
  kubectl create role notes-pod-reader --verb=get,list --resource=pods
  kubectl create rolebinding notes-pod-reader --role=notes-pod-reader --serviceaccount=default:notes-reader

  kubectl auth can-i get pods --as=system:serviceaccount:default:notes-reader
  kubectl auth can-i delete pods --as=system:serviceaccount:default:notes-reader
  kubectl auth can-i get secrets --as=system:serviceaccount:default:notes-reader

You want: yes  /  no  /  no

  kubectl delete rolebinding notes-pod-reader
  kubectl delete role notes-pod-reader
  kubectl delete sa notes-reader

  [ ] can-i get pods was yes, delete pods was no
