Lecture 3 networking lab
Goal: use curl -v and say WHY a request failed.
No AWS console. No new Python app.


--------------------------------------------------
A. Start notes-api (leave this window open)
--------------------------------------------------

  cd lec-02/codebase/notes-api
  python notes-api.py

You should see: API is running at http://127.0.0.1:8080

Open a SECOND terminal for the rest.


--------------------------------------------------
B. A working call (this is HTTP, no DNS)
--------------------------------------------------

  curl -v http://127.0.0.1:8080/health

Look for:

  Trying 127.0.0.1:8080
  Connected to 127.0.0.1
  GET /health
  HTTP ... 200

127.0.0.1 is this laptop. There is no DNS lookup for it.


--------------------------------------------------
C. DNS then HTTPS (the internet)
--------------------------------------------------

  curl -v --max-time 15 https://example.com

Look for, in order:

  1) Resolving example.com  (DNS: name -> IP)
  2) Trying <an IP>:443     (TCP to port 443)
  3) SSL / TLS handshake    (HTTPS)
  4) GET /                  (HTTP)
  5) HTTP ... 200

If DNS fails, you never reach TLS. Write down which line you saw first.


--------------------------------------------------
D. Connection refused (nothing is listening)
--------------------------------------------------

  curl -v --max-time 5 http://127.0.0.1:9

Port 9 is almost never used. You should see:

  Connection refused

Meaning: the IP was reachable. No program is listening on that port.
This is NOT 404. HTTP never started.


--------------------------------------------------
E. Timeout (packets disappear)
--------------------------------------------------

  curl -v --max-time 5 http://192.0.2.1:80

192.0.2.1 is a documentation address. It should not answer.

You should see curl wait, then:

  Connection timed out
  or  Operation timed out

Meaning: no reply. Could be a firewall dropping packets, or a dead route.
Different from refused: refused is a fast "no". Timeout is silence.


--------------------------------------------------
F. 403 (HTTP worked; you are not allowed)
--------------------------------------------------

  curl -i --max-time 15 https://httpbin.org/status/403

You should see HTTP 403.

Meaning: TCP and TLS worked. The server understood you and said no.
This is NOT connection refused.


--------------------------------------------------
G. Say it out loud (fill this in)
--------------------------------------------------

  Working notes-api:     ______________________________
  example.com HTTPS:     ______________________________
  Port 9:                ______________________________
  192.0.2.1:             ______________________________
  httpbin 403:           ______________________________

Cheat phrases:

  200         = HTTP worked
  403         = HTTP worked, not allowed
  404         = HTTP worked, path is wrong  (lecture 2)
  refused     = nothing listening on that port
  timeout     = no answer (often a firewall or a dead IP)
