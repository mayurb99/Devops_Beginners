Lecture 7 — Kubernetes on EKS (console)
You already packed notes-api and ran it on Fargate (lecture 6).
Today you put the same app on a Kubernetes cluster that you create in the AWS console.
The image lives in ECR. The browser opens a public URL from a Service of type LoadBalancer.
That Service asks AWS for a hostname. You do not click Create load balancer in the EC2 console.

Windows has no Docker Desktop. You build the image on one Amazon Linux EC2 (same idea as lecture 5).
kubectl runs in CloudShell (a terminal inside the AWS console). You do not install kubectl on Windows.

Need: a browser, Git Bash (only for SSH to the build EC2), the SAME Region as lectures 4–6.
You do not rewrite notes-api.py. You do not invent YAML.

Clock: about 75 minutes. Start the EKS cluster as soon as the VPC and IAM roles exist.
The cluster takes 10–15 minutes. You push the image to ECR while you wait.
Cleanup is part of this class. EKS is billed even with zero Pods.

  0–18 min    read the deck (why not Fargate only, then Kubernetes words)
 18–28 min    VPC + IAM roles + ECR
 28–32 min    click Create cluster (then leave it cooking)
 32–48 min    build notes-api:l7 on a tiny EC2, push ECR
 48–62 min    node group, CloudShell, apply YAML, wait for EXTERNAL-IP
 62–68 min    open the HTML page, Add note, Show notes
 68–75 min    delete Service, node group, cluster, EC2, VPC


--------------------------------------------------
Money — read this before any Create button
--------------------------------------------------

EKS control plane ≈ 0.10 USD per hour even if no Pods are running.
The LoadBalancer Service creates an AWS load balancer (billed) until you delete the Service.
Two t3.small nodes use hours. One t3.micro build box uses Free Tier hours if you still have them.

If you leave the cluster overnight you get a bill.

A. VPC for Kubernetes  (console)
--------------------------------------------------

EKS needs two Availability Zones. A LoadBalancer Service needs public subnets
that can reach the internet. You do not create NAT today. Nodes sit in public
subnets with a public IP so they can pull ECR without NAT.

Do not reuse lecture 4’s notes-net if it still has a NAT. This VPC is only for today.

1. Search: VPC
2. Create VPC
3. Resources to create: VPC and more
4. Fill in:
   Name tag: notes-k8s
   IPv4 CIDR: 10.7.0.0/16
   Number of Availability Zones: 2
   Number of public subnets: 2
   Number of private subnets: 0
     If the form will not accept 0, set private to 1 and never put nodes there.
   NAT gateways: None
   VPC endpoints: None
   Enable DNS hostnames: Yes
5. Create VPC
6. Wait until it finishes. Open VPC notes-k8s.
   VPC ID = _______________________________

7. Left: Subnets. You should see two public subnets in two different AZs.
   For EACH public subnet:
   - Click it → Actions → Edit subnet settings
   - Enable auto-assign public IPv4 address → Save
   - Tags → Add tag
       kubernetes.io/role/elb  =  1
   - Add tag
       kubernetes.io/cluster/lec07-eks  =  shared

   Those tags tell Kubernetes “put the public load balancer here.”

Write the two subnet IDs:
  public-a = _______________________________
  public-b = _______________________________

  [ ] VPC notes-k8s exists, two public subnets, auto-assign IPv4 on, two tags on each


--------------------------------------------------
B. IAM roles  (console) — three roles
--------------------------------------------------

Kubernetes on EKS uses roles. You do not paste access keys into a Pod.


B1. Cluster role  (the control plane)

1. Search: IAM → Roles → Create role
2. Trusted entity: AWS service
3. Use case: EKS  →  EKS - Cluster  →  Next
   (If you do not see EKS - Cluster: use EKS and pick the cluster trust.)
4. Policy AmazonEKSClusterPolicy should already be ticked → Next
5. Role name: lec07-eks-cluster-role
6. Create role


B2. Node role  (the worker EC2s)

1. IAM → Roles → Create role
2. Trusted entity: AWS service → EC2 → Next
3. Tick ALL three:
     AmazonEKSWorkerNodePolicy
     AmazonEKS_CNI_Policy
     AmazonEC2ContainerRegistryReadOnly
   Next
4. Role name: lec07-eks-node-role
5. Create role

AmazonEC2ContainerRegistryReadOnly lets the node pull your ECR image.
Without it the Pod stays ImagePullBackOff.


B3. Build-box role  (so the tiny EC2 can push to ECR)

1. IAM → Roles → Create role
2. AWS service → EC2 → Next
3. Tick AmazonEC2ContainerRegistryPowerUser → Next
4. Role name: lec07-ec2-ecr
5. Create role

  [ ] three roles exist

D. Create the EKS cluster NOW  (console) — then let it cook
--------------------------------------------------

Do not wait for Docker. Cluster create is the slow step.

1. Search: EKS  (Elastic Kubernetes Service) → Clusters → Create cluster
2. If you see Quick configuration vs Custom, choose Custom
3. Name: lec07-eks
4. Kubernetes version: leave the default
5. Cluster service role: lec07-eks-cluster-role
6. Networking
   VPC: notes-k8s
   Subnets: BOTH public subnets from section A
   Security groups: leave the default for that VPC
   Cluster endpoint access: Public
7. Cluster access / authentication
   Turn ON the option that gives the cluster creator administrator access
   (wording: “Allow cluster administrator access” or “include cluster creator”).

8. Add-ons: leave the defaults (vpc-cni, kube-proxy, CoreDNS)

If clone has no lec-07, paste the two files yourself.

deployment.yaml (IMAGE already replaced with ${URI}:l7):

apiVersion: apps/v1
kind: Deployment
metadata:
  name: notes
spec:
  replicas: 1
  selector:
    matchLabels:
      app: notes
  template:
    metadata:
      labels:
        app: notes
    spec:
      containers:
        - name: notes
          image: PUT-YOUR-URI-HERE:l7
          ports:
            - containerPort: 8080
          env:
            - name: HOST
              value: "0.0.0.0"
            - name: PORT
              value: "8080"

service.yaml:

apiVersion: v1
kind: Service
metadata:
  name: notes
spec:
  type: LoadBalancer
  selector:
    app: notes
  ports:
    - name: http
      port: 80
      targetPort: 8080

Create them:

  nano deployment.yaml
  nano service.yaml
  kubectl apply -f deployment.yaml
  kubectl apply -f service.yaml

--------------------------------------------------
I. If the Pod is not Running
--------------------------------------------------

  kubectl describe pod -l app=notes
  kubectl logs -l app=notes

ImagePullBackOff
  Image URI wrong, missing :l7, or node role missing AmazonEC2ContainerRegistryReadOnly.
  Fix the Deployment image, kubectl apply -f deployment.yaml again.

CrashLoopBackOff
  App exited. logs will show the Python error. Use the lecture 7 notes-api file.

Pending
  Nodes not Ready, or not enough CPU/memory. Wait for the node group.

J. Open the HTML page on your Windows browser
--------------------------------------------------

1. Paste http://EXTERNAL-IP/ into Chrome or Edge. Use http, not https.
2. You should see the notes-api page: a text box, Add note, Show notes, and two starter notes.
3. Type a line. Click Add note. Click Show notes. The new line should appear.
4. Bottom of the page: “This page was served by Pod: …” — that name is this one Pod.

If the tab spins forever:
  The node security group is not allowing HTTP in.
  EC2 → Security Groups → the group on the EKS nodes (name contains lec07-nodes or eks)
  Inbound → Add:
    Type HTTP, port 80, source 0.0.0.0/0
    Type Custom TCP, port 30000–32767, source 0.0.0.0/0
  Save. Refresh the browser. Delete these rules in section Z with the cluster.

If you see {"error": "not found"} you opened a path that is not /.
If you see old JSON only, the image is lecture 6, not :l7. Check the Deployment image.

--------------------------------------------------
Z. Cleanup  (do this before you stand up)
--------------------------------------------------

Order matters. The load balancer exists because of the Service. Delete the Service first.

CloudShell:

  kubectl delete svc notes
  kubectl delete deploy notes

Wait until EC2 → Load Balancers no longer shows the one Kubernetes created
(or it is gone after a minute).

Console:

1. EKS → lec07-eks → Compute → node group lec07-nodes → Delete
   Wait until it is gone.
2. Cluster lec07-eks → Delete cluster. Type the name. Wait until it disappears.
   The control plane charge stops when the cluster is gone, not when Pods are gone.
3. EC2 → Instances → lec07-build → Terminate
4. EC2 → Security Groups → lec07-build-ssh → Delete
   Node / cluster security groups often delete with the cluster. If any lec07 leftover remains, delete it.
5. ECR → notes-api → you may delete the repository, or leave it for lecture 8 and delete then.
6. VPC → Your VPCs → notes-k8s → Actions → Delete VPC
   The wizard can delete subnets, IGW, and route tables together.
   If Delete is grey: a leftover ENI or load balancer still exists. Refresh, wait, try again.
7. IAM → Roles → delete lec07-eks-cluster-role, lec07-eks-node-role, lec07-ec2-ecr

  [ ] No EKS cluster, no leftover load balancer, VPC notes-k8s gone, build EC2 terminated


--------------------------------------------------
If something fails
--------------------------------------------------

Create cluster stuck / failed
  Cluster role is not lec07-eks-cluster-role, or subnets are in one AZ only, or you used lecture 4’s private subnet.

kubectl Unauthorized
  Cluster creator access was off. Add an access entry with AmazonEKSClusterAdminPolicy.

nodes 0
  Node group still creating, or node role missing AmazonEKSWorkerNodePolicy / AmazonEKS_CNI_Policy.

ImagePullBackOff
  URI Region does not match, tag is not l7, or node role cannot read ECR.

EXTERNAL-IP pending more than 10 minutes
  Public subnets missing tag kubernetes.io/role/elb=1, or auto-assign public IPv4 is off.

Browser hangs
  Node security group has no 80 (section J).

Add note works, Show notes loses it after you deleted a Pod
  That is expected. Memory died with the process. Lecture 8 talks about two replicas.
