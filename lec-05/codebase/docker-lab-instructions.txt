Lecture 5 — Docker lab
Docker runs on Amazon Linux EC2. Windows has no Docker Desktop.
The console starts the Linux computer. Git Bash is only for SSH after that.

Need on Windows: a browser (AWS console), Git Bash, the same Region as lecture 4.
You package notes-api. You do not rewrite the Python.

CLI-0 to CLI-3 = console buttons. No aws commands.
CLI-4 onward = Git Bash ssh / scp, then sudo docker on the EC2.

D. Run the container and call /health
--------------------------------------------------

Window 1 (EC2):

  sudo docker run --rm -p 8080:8080 --name notes-l5 notes-api:l5

Leave this window open. You should see:
  API is running at http://0.0.0.0:8080

Window 2 (second SSH, same EC2):

  curl http://127.0.0.1:8080/health

You should see: {"status": "ok"}

-p left  8080 = door on THIS EC2 (the host)
-p right 8080 = door INSIDE the container
You curl the host. You are sitting on the host, so 127.0.0.1 is the EC2, not Windows.

  curl http://127.0.0.1:8080/notes

Do not curl the EC2 public IP from Windows. Port 8080 is not open in the security group.

F. Port mapping (the door)
--------------------------------------------------

-p 8080:8080 means:
  left  8080 = door on the HOST (this EC2)
  right 8080 = door INSIDE the container (the Python app)

Window 1: Ctrl+C.

  sudo docker run --rm -p 9090:8080 --name notes-l5 notes-api:l5

Window 2:

  curl http://127.0.0.1:9090/health     # works
  curl http://127.0.0.1:8080/health     # fails — nothing on host 8080 now

Ctrl+C the container. Run the usual mapping again:

  sudo docker run --rm -p 8080:8080 --name notes-l5 notes-api:l5

  [ ] I saw 9090 work and 8080 fail when mapped that way

G. Environment variables  (PORT must match the RIGHT side of -p)
--------------------------------------------------

-e PORT=… sets the door INSIDE the container (the Python app).
That number must be the RIGHT side of -p. You still curl the LEFT side
on the EC2.

If the name notes-l5 is already in use:

--------------------------------------------------
H. Volume (a folder that outlives the container)
--------------------------------------------------

Notes live in memory. A volume does not magically save them unless the app writes files.
Today we only prove the mount exists.

Ctrl+C.

  sudo docker run --rm -p 8080:8080 -v notes-data:/data --name notes-l5 notes-api:l5

Window 2:

  sudo docker exec -it notes-l5 ls /data
  sudo docker exec -it notes-l5 sh -c "echo hello > /data/from-container.txt"
  sudo docker exec -it notes-l5 cat /data/from-container.txt

Ctrl+C (container gone). Run again with the SAME volume name:

  sudo docker run --rm -p 8080:8080 -v notes-data:/data --name notes-l5 notes-api:l5

  sudo docker exec -it notes-l5 cat /data/from-container.txt

You should still see hello. The container died. The named volume did not.

  sudo docker volume ls

  [ ] File survived a new container via the volume


--------------------------------------------------
I. stop, start, rm  (without --rm)
--------------------------------------------------

Ctrl+C if a --rm container is still up.

  sudo docker run -d -p 8080:8080 --name notes-l5 notes-api:l5

-d = detached (runs in the background). No --rm, so the container stays after stop.

  sudo docker ps
  sudo docker stop notes-l5
  sudo docker ps
  sudo docker ps -a          # notes-l5 is there, Status: Exited
  curl http://127.0.0.1:8080/health    # fails — process is off

  sudo docker start notes-l5
  curl http://127.0.0.1:8080/health    # works again

  sudo docker rm -f notes-l5
  sudo docker ps -a          # notes-l5 is gone
  sudo docker images         # the IMAGE notes-api:l5 is still there

stop = the process is off. rm = delete this container. The image remains.

  [ ] stop, start, rm all behaved as above


--------------------------------------------------
J. Why lecture 2's 127.0.0.1 bind would fail in Docker
--------------------------------------------------

Lecture 2 listened on 127.0.0.1. Inside a container that means
"only this container, not the mapped port."
This copy uses 0.0.0.0 so -p 8080:8080 can reach it.
You do not need to demo a failing file unless the tutor asks.
